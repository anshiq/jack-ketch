The problem

Agents block on foreground commands. Dev servers never return.

Run npm run dev in an agent's shell and the session hangs. Detach it and the logs are gone, the port is orphaned and nobody knows whether it started. jack-ketch owns the process so the agent can ask questions instead of babysitting.

Daemon-owned processes

One daemon per OS user hosts every project. Processes outlive agent sessions, so a later session re-attaches with list_processes instead of starting a duplicate.

Logs you can search

stdout and stderr are captured to a ring buffer and an FTS5 index. Filter by stream, level, substring or regex, across every process in the project.

Readiness, not guessing

Readiness patterns, HTTP and TCP health checks and restart policies. wait_for_log returns when the server says it is up, capped per client so no tool call times out.

Failures explained

diagnose_process names the category, shows evidence and says who has to act: you for missing env, the agent for code errors, the agent after your approval for installs and migrations.

Probe and verify

probe sends a request to the running app and returns the response plus the log lines it produced. Save the useful ones as checks and re-run them with run_checks.

Credentials without secrets

Store test JWTs, cookies and API keys in the web UI. The agent calls your API as a real user by profile name and never sees a value. Encrypted at rest, scrubbed from every result and log.

How it fits together

A thin MCP bridge in front of one always-on daemon.

Your agent talks to jack-ketch serve, a thin stdio or HTTP bridge. The bridge calls jackketchd over a 0600 Unix socket. The web UI uses the same API over an authenticated loopback listener. State lives in a single SQLite database.

  • Socket directory 0700, peer-credential uid check, fail closed
  • TCP listener off by default, bearer token, strict Host and Origin checks
  • Every mutating call and policy denial is audited for 90 days

Config that follows the project

Modes, ordered env and saved runs.

Apps are auto-detected and stored in the daemon database, not in your repository. Each app can run several ways. When a hand-built run works, jack-ketch asks you whether to save it as a mode.
